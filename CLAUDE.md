# checkit-printit

@../checkit/WORKING_RULES.md

The line above loads the house rules shared by all three repos. They start
with a duty: **check that student names are masked before anything else.**
Here that matters most -- this repo is the one that handles names.

Turns a CheckIt bank plus a roster into a printable class set, and keeps
the course around it: roster, seating, the Google Form, the print record,
scanning marked papers back in, Progress, the gradebook round-trip, the
vault. The local web app (`gui/`) is part of this repo. Whole-project
overview: `../checkit/CLAUDE.md`. To-do list: `../checkit/ROADMAP.md`.
Design record: `DESIGN.md`. History: `../checkit/CODEBASE_NOTES.md`.

**"Old map › X"** below means the section "X" under "printit's map, as it
stood before 2026-11-17" in the notes, where this file's long form lives.

```bash
./.venv/Scripts/python.exe tools/check.py        # everything, one exit code
./.venv/Scripts/python.exe tools/docs.py         # do the docs still match the code?
./.venv/Scripts/python.exe tools/audit.py        # after any rename or new command
./.venv/Scripts/python.exe -m pytest -q
./.venv/Scripts/python.exe -m checkit_printit --help
```

This venv has **both** packages installed editable, `checkit-printit` and
`checkit-dashboard` (pointing at `../checkit/dashboard`), so the platform's
tests run here too. Reading a scan needs `pypdfium2`, `zxing-cpp`, `numpy`
and `pillow`, all declared.

`tools/check.py` is the one to run before a commit: both suites and the
audit, one exit code, three lines -- so nobody reaches for `| tail`. A run
that collected no tests fails. `tools/verify_run.py <job> <out>` checks a
finished run against its job, and a check that examined nothing fails.

## Where things live

Everything with a name in it is outside every repo, under
`~/CheckItPrintIt/` (`CHECKIT_PRINTIT_HOME` moves all of it):

| path | holds |
|---|---|
| `courses/<name>/` | the course: `course.toml roster.toml seating.toml room.json availability.toml form.toml gradebook.toml job.toml record.db secrets/ scans/` |
| `jobs/<title> <date>/` | a **job**: `publication.toml` and little else |
| `<course>/<title> <date>/` | a **run**: `main.pdf main.tex manifest.toml main.pages compile.log`, a folder per skill |
| `vaults/<course>.json` | the pseudonym table. A **sibling** of `courses/`, so masking a course folder cannot reach it. No recovery key, on purpose |
| `name-guard.toml` | what the name guard lets through: invented courses, words cleared by him, files of common names. Real words, so never committed |

"Open the folder" means the run, not the job; opening the job looks like a
failed build. One course folder may be one course or two sections; nothing
derives it from the course code. A job names its course with `[course]
folder = "..."` (`folder`, not `name` -- `name` is the printed header).

**Three records, not substitutes for one another:**

| | answers | written by |
|---|---|---|
| `manifest.toml` | which `(skill, version, seed)` were **drawn**, so a run can be replayed | Python, before the compile |
| `record.db` `printed` | which **student** got which paper | Python, after the folder is written |
| `main.pages` | which **page** each paper landed on | **TeX**, as it ships pages -- a skill can run to two sheets |

`record.db` also holds `run` (with `run_no`, `graded`, `delisted`,
`rebuilt`), `attempt` (the only table an outcome is read from: `passed`,
`queried`, `failed`, `absent`), and `meta.last_run_no`, the high-water mark
so a deleted run's number is never reissued. `connect()` migrates only when
the file's `user_version` is not `SCHEMA_VERSION`. A trigger refuses
deleting a run with marks.

## What a printed page carries

- **The footer code**: a QR of `C1-<run_no>-<page>`, 9mm, level M. The run
  **number**, never the draw seed -- a replay shares its seed. Kept to 14
  bytes so the symbol stays version 1 (a test measures it).
- **`main.pages`**: `run*7`, then `page*kind*sid*skill*version*sheet` per
  page and `mark*page*label*x y w h d` for the `box`, `id` and `name`
  marks. `kind` is `student`, `spare` or `key`. Blank padding writes
  nothing, so the gaps are the blanks.
- **The id grid**, on a paper printed without a name: nine 4.4mm cells. The
  recogniser (`digits.py`, weights in `data/digits.npz`, regenerated by
  `tools/train_digits.py`) scores every roster id against the cells and
  refuses below `ACCEPT` or within `MARGIN` of the runner-up. A test keeps
  `scans.py`'s grid sizes equal to `printit.sty`'s.

| macro `main.tex` emits | does |
|---|---|
| `\setrunid{N}` | **the gate**: opens `main.pages` and turns on the index, marks and code. Emitted only when the run has a record |
| `\setkind{...}` | `student`, `spare` or `key` for what follows |
| `\setsid{...}` | the student id; empty draws the grid |
| `\setname` / `\setsect` / `\setvseed` | the name, section and version seed |
| `\setboolean{anstoggle}{true}` | answers on, before the answer keys |

Absence means **on**: `main_tex` writes `\cipidfalse` / `\cipcodeonfalse`
only to turn the id field or the code off, so a newer document compiles
against an older theme. Other off switches: `[noid]`/`[nocode]` package
options, `build --no-ids`/`--no-codes`,
`[print] ids/codes = false`, and `build --no-record` (no code: nothing to
look it up in). `names = false` with `ids = false` is warned about, not
refused. **A theme change reaches an existing bank only through
`install --force`**, which is his call.

## Footguns, by subject

### Building

- **One folder is one run.** The output folder is `{title} {date}` and that
  is the run's identity. A build whose papers differ from what the record
  says that folder produced is refused (`FolderInUse`); `--replace` goes
  through, `--replay` is exempt, and a graded run is refused outright.
  `--rebuilt` recovers a lost index: the page mapping comes back exactly,
  the seeds do not, and the run is marked. Old map › "One folder is one
  run, and a second job is refused".
- **A hand-built run is not the run he set up.** `printjob.publication_text`
  and `write_job`, from `courses/<name>/job.toml`. Old map › "A hand-built
  run is not the run he set up".
- **An unchosen variant is refused.** R1, R2, W4, W4-E, W5, W7, N3, N4 and
  D2 declare variants; a dealt paper from one needs a `[variants]` line.
  `Bank.variant_labels(slug)` is the one answer to "has variants".
- **`build` exits non-zero when the record was not written.** Rebuild
  before handing anything out.
- **The seating chart is the print list**, and dropping removes a student
  from the whole run: `Roster.live()` is applied in `assemble` *and*
  `build_handouts`, on purpose, each with its own test.
- **`choose_seeds` draws without replacement** per skill; `[seeds.<skill>]`
  pins one letter of one skill and the flat `[seeds]` form is refused above
  one skill. `manifest.toml` records the result, so `--replay` survives
  edits; a changed variant or generator is refused.
- **The header has no slack.** Every slot has an explicit width; the name
  is scaled past 2.1in. Judge on a real title with a real name. Old map ›
  "The header and footer have no slack, and fancyhdr does not clip".
- **A LaTeX package can take a name you are using** (`qrcode.sty` took
  `\xa`). No bare, unnamespaced control sequence in either `.sty`; a figure
  and the footer code must share a test document; `@` is not a letter
  everywhere in `printit.sty`. Old map › "A LaTeX package can take a name
  you are already using".
- **Text into LaTeX goes through `assemble.tex_escape`**, except the
  student id, which the page index records verbatim.

### Course state

- **TOML files are edited by line, never parsed and re-dumped** -- they
  carry hand-written comments. `seating.blank_seat`,
  `availability.set_values`, `course.save_identity`. A string goes through
  `fileio.toml_string`, a file through `fileio.atomic_write`.
- **`course.toml` is read by `course.config` / `config_at` / `bank_path`**,
  nothing else. `[passing]` holds thresholds (default 1), not `bank.xml`.
  `\date` and `\author` (semester, instructor) come from it too.
- **`skills` sits under `[assessment]`** in `availability.toml`, which is a
  local copy of what the form offers and can drift; `nothing_to_say()`
  refuses a push with no skills or no date.
- **Only `form pull` dates a choice** (`chose_for`); an undated choice is
  "unknown", never agreement.
- **A seat carries the student id**; `Chart.order` matches on it first.
  `room.json` and `seating.toml` are not duplicates -- the same save writes
  both, and `seating.disagrees_with_room` refuses a build on a divergence.
- **The draft carries only what its mode uses** -- `simply_print` in
  `same`, `default_when_missing` / `append_for_everyone` in `chose`.
- **`roster import` of a Brightspace list needs `--covers`**, or a file
  naming no section marks the other section dropped.
- **Email is a weak key**: addresses accumulate, the primary never moves.
- **`course init --adopt` can hand you a chart Seating will not overwrite**
  (`seating.was_generated`). Old map › "Where things stand".

### Scans

- **Order carries nothing**: every page is placed by its own code. Five
  statuses (`placed`, `blank`, `unreadable`, `foreign`, `unknown-run`);
  `unknown-run` now says why. `missing` counts students' papers only.
- **The mark is read in colour**, and the box is found by template match,
  not assumed. **Scan in colour.** The code places the page and the found
  box pins it. Old map › "The mark is read in colour, and the box is found,
  not assumed" and "The code places the page; the box pins it".
- **A read adds to the pile**; reading a file again replaces its pages;
  `clear()` is the only way back.
- **The browser sends judgment and nothing else**: `/api/scan/save` takes
  `{id, outcome}`; who, which skill and which page come from the server's
  copy of the read, so a stale page cannot attach a decision to the wrong
  student.
- The calibrated numbers are listed in the roadmap; each was fitted to one
  stack.

### The gradebook

- **`gradebook.produce` is the export**, for the CLI and the app: splice,
  verify, byte check, record audit, trim. It takes rows **from the header
  down**, read by `gradebook.rows_of` (unstripped) -- never
  `classlist.read_rows`, which strips. CSV only.
- **His `~/Downloads/Student_PDFs/Skill_Checker/apply_to_brightspace.py` is
  the specification.** A pass goes into an empty or not-yet cell; a
  non-pass only for a skill named in `--not-yet` and only into an empty
  cell; **a pass is never replaced** (no flag exists, and a test says so);
  an absence writes nothing; anything else in a cell stops the export.
- **The import file carries the identifier, the skills written and the
  end-of-line marker**, nothing else -- an allowlist. Old map › "Export
  fills cells; it does not generate a file".
- **Match on `OSW_ID`**, not an email (stale from other institutions). An
  ignore marker (`-DoNotUse`) is looked for in every column. A section is
  read after a hyphen. **The report names rows, never students.**
- `gradebook.toml` carries no student data, so a mapping can be worked out
  against a masked twin.

### The vault and masking

- **`CHECKIT_PRINTIT_MASK_NAMES`** -- see the house rules. `privacy.saw` is
  called by `roster.load`, `seating.load` and `roster import`; `install()`
  wraps stdout and stderr in the CLI's entry point. A file outside a course
  folder goes to the `unfiled` vault. **The test suite unsets it in
  `conftest.py`, at import** -- an autouse fixture ran too late for a
  module-scoped fixture and wrote a vault into the real home.
- **A twin is checked before it is handed over** -- read back and searched
  for every real value; a two-letter value is a leak as a whole cell. On a
  failure it is deleted and the message names columns, never values.
- **An unrecognised column holding free text is blanked**; a short-valued
  "category" is kept only if every value repeats and none is a name;
  `<Selectbox>` columns are kept.
- **Substitute in one pass**, never pair by pair (`Vault._apply`), and
  person tags unmask in lower case only.
- **`with sqlite3.connect(...)` does not close the connection**, and text
  must be read and written with `newline=""`. Old map › "Student names
  never reach chat or a commit".
- `mask-course` never copies `secrets/` or `scans/`.
- **The name guard** (`nameguard.py`, DESIGN 20) refuses a commit, a
  commit message, a merge or a push that adds a real student's name
  word, id or address, in all three repos: `githooks/`, which each repo
  names in `core.hooksPath` (local config). Real is every roster,
  seating chart and vault under the home except `invented_courses`.
  Whole words only; names as written or in capitals. It fails closed.
  A seat is a `Seat`, not a string -- the first version read no chart
  at all. A vault is read per person, not by `real_values()`, whose
  address domains made `edu` a name.

### Google

- **Push and pull need no Google sign-in**: they are an HTTPS POST with the
  secret in `secrets/form-secret.toml`. clasp is for creating and
  deploying only. A lapsed clasp sign-in stops nothing but provisioning.
- **The web app URL is a credential too**; both live in `secrets/`, never
  in `form.toml`.
- printit owns four slots on the form; the rest is his.
  `reference/control_center.gs` is the specification for wording.
- **If the app ever tells someone to run a CLI command, that is a bug.**

### Emailing students (DESIGN 21)

- **`mailing.py` holds every rule**; the Prior assessments page and its
  routes (`/api/email/*`) only gather and draw. Mail goes through the
  form's script (`mail` op, `MailApp`), as the form's owner -- the only
  Google identity printit has. One request per student.
- **The script must report version 2** (`ping`); an older one is refused
  before the first email. Settings' "Update the script" pushes and
  `update-deployment`s (same URL), and then **every call, push and pull
  included, waits** until he grants the new permission once.
- **A `mail` request is never retried and a timeout is never recorded**
  (`form.FormTimeout`): Google may have sent it. Everything else in
  `form.call` still retries.
- **`mailed` records what each email said, per skill**; a student is due
  again when a mark changes. Only `due` letters are sent.
- **The template is the home's** (`email.toml`, every course), Mustache
  field tags only, read by `mailing.render` -- not pystache, which lets an
  unclosed section through even in strict mode. An unknown field refuses.
- **The words are the gradebook matching's** (`[marks]`), else "Pass" /
  "Not yet", and the page says which.
- **A paper's later sheets** are stored against its student by
  `_note_pages` through `Index.first_page_of`; before 2026-11-19 they
  were saved with nobody on them, and the page warns of a short paper.

### Names (DESIGN 22)

- **Four stored parts**:
  - `first` and `last` are the registrar's, and an import refreshes them;
  - `pref_first` and `pref_last` are the instructor's, and no import
    touches them.

  `name` is the registrar's whole name, the weakest key, and follows
  First and Last when the Roster edits them. A roster with `preferred` is
  refused: that was the old whole-name field.
- **`Student.display` is the printed name, the one rule**: (pref else
  registrar) first + last, once `first` and `last` are both stored;
  `name` until then. Every surface that shows a student reads it.
- **`Student.name_fields()` is the one list the privacy paths read**:
  `maskcourse` (and so `privacy.saw`) and `nameguard`. Add a name field
  there or it leaks. A second surname for one person gets its own fake
  (`Vault._candidates`).
- **The Roster**:
  - the name columns are First, Last, Pref first and Pref last, each an
    ordinary sortable column;
  - the switch reorders both pairs in place (`orderRosterColumns`);
  - a save that would leave half a name is refused
    (`_check_name_parts`).
- **Progress keeps one name column**, sorted on the shown parts
  (`_shown_sort`). **Scans shows the name the record printed**, which is
  history and unchanged.

## The web app

`checkit-printit gui -c COURSE` serves one course on `127.0.0.1`, never
`0.0.0.0`. It requires a per-run token as a header, and refuses any `Host`
but 127.0.0.1 or localhost (a page rebinding its own domain to loopback
could otherwise read the token). All eight views are built: Roster, Update
form, Print job, Runs, Scans, Progress, Seating, Settings (`VIEWS` in
`app.js`).

**Every handler calls the function the CLI calls**, never a copy:

| rule | lives in |
|---|---|
| the name to show | `Student.display` |
| version letters a run needs | `assemble.versions_for` |
| ids a per-run table may use | `roster.keys_of` |
| a per-student override | `roster.apply_overrides` |
| which bank a course prints from | `course.bank_for` |
| reading responses | `responses.pull_for_course` |
| connecting a form | `provision.py` |
| the room, and who sits where | `room.py`; the chart it produces is `seating.to_toml` |
| dropping a student | `roster.set_dropped` |
| the open list, the assessment | `availability.set_open`, `set_assessment` |
| the form's wording | `form.payload_for`; fixed text `boilerplate.py` |
| building | `runner.run`; a draft becoming a job folder, `printjob.py` |
| emailing a run's students | `mailing.plan`, `compose`, `send`; the script update, `provision.update_script` |
| the gradebook export | `gradebook.produce` |

If the GUI needs a rule still inside a `@click.command`, move it out.

**Working on it**: use `Scratch 48` (48 synthetic students shaped like the
real roster) for layout and `Demo` (`printit-demo`, eight invented
students at `example.invalid`) for everything else. `Demo` is the one
test course on purpose: anything that needs a Google Form borrows one
for the test and gives it back (DESIGN 21, "Testing without emailing
anyone"). The browser pane's servers come from `.claude/launch.json` in
the **session's** working directory (`../checkit`). Then:

- **Restart the server after editing `gui/`** -- Python does not reload a
  live module, and the front end falls back rather than erroring.
- **A stale `index.html` will convince you Seats is broken**: load
  `/?cb=1#seating` and compare before believing a regression.
- **"Failed to fetch" means a handler died**; every exception now returns a
  500 naming it and prints the traceback.
- **Check at the pane's real width**, about 530px.
- **Test a destructive action on a throwaway course**, and copy `Scratch 48`
  aside first; its pinned hashes are in Old map › "A fixture small enough to
  be convenient hides what you are measuring".

**The front end's rules** (DESIGN 13 is the design document; read it
before changing anything visual):

- **Everything is a token**: no raw hex, radius or gap. One hue, OKLCH
  260. Figtree is vendored, never a CDN.
- **Never `confirm`, `alert` or `prompt`** -- the desktop app's pane
  suppresses them silently. `ask()` and `askFor()` over `askBox`; a test
  forbids the natives, qualified or not.
- **One save bar per tab** (`saveBar(view, dirty, what)`), absent when
  clean; `.warnline` draws its own `⚠`; `.emptystate` says what is missing
  and the way out; sentence case on labels; a Print-tab section is an
  `.annot`.
- **No control beside the scan drop area**, no facts run together with
  separators, explanations behind a `?`, headings of two or three words.
- **`app.js` and `seating.js` share one global scope**, and `style.css` and
  `seating.css` one document: a test fails on a name or bare class
  defined in both. A class that takes an element out of flow is never a
  modifier. **Never hide a column by `nth-child`.**
- **A glyph strokes itself** (`class="glyph"`); any rule giving a glyph a
  width sets `--glyph-size` to the same number. One line weight, 1.5px.
- **Pointers**: a control inside `.paper` must be excluded from its
  `pointerdown`; a `pointermove` checks `e.pointerId`; a second finger
  calls the one-finger gesture off.
- **`seats_of` is a view, not the seats** -- writes to it are lost; change
  seats through `room.live_seats`. **The seat sweep exists twice on
  purpose** (`room.seat_sweep`, `slotsOf`), held by
  `TestTheSweepMatchesTheCanvas`.
- **"Data arrived" is not "tab drawn"**, and `show()` writing
  `location.hash` must not re-trigger itself. Old map › "What is slow, and
  where the waiting happens".
- The markup tests (`tests/test_gui_markup.py`) are the only tests that
  read `index.html`; run them after any markup change.

**More, briefly** -- each a rule that once cost something:

- **Nothing on the Roster writes before Save**, drops included; they apply
  before field edits, since the drop matches on name.
- **Only warn when something is at stake.** `okDespitePending` asks about
  unsaved work on other tabs; any new "is this tab dirty" predicate must be
  false for a tab never opened.
- **A sticky table cell needs `border-collapse: separate` and no
  `overflow: hidden` between it and the scroller**; a hidden element
  measures zero, so never size columns while a tab is hidden.
- **One `--gutter`, applied by `main` alone**, and a media query never
  selects a bare tag name. A page heading is `.pagename`.
- **A skill has two names**: `Bank.skill_title` for tables and headers,
  `Bank.description` (the "I can..." line) for tooltips.
- **Runs**: a graded run cannot be delisted, grading un-delists, delisting
  never deletes, and reprint (replay the manifest) and reuse (load the
  settings, write nothing) are separate.
- **`[selection] only_students` has three states**: absent is the class, a
  list is those students, `[]` is a mistake `assemble` refuses.
- **Progress**: a pass count only where the threshold is above 1, an
  attempt count only when surprising, passing is quiet and `.stuck` is
  loud. DESIGN 14.3 and 17.
- **The CLI flags `--ids`/`--codes` default to `None`** ("whatever the
  publication says"), never `False`.
- **A run's folder compiles with `pdflatex main.tex` alone**; figures are
  copied by scanning the written `.tex`, so a `textemplate.tex` chooses in
  Jinja which files it names.
- **The CLI reconfigures stdout with `errors="backslashreplace"`** in
  `main()` -- a cp1252 console died half way through a report on an emoji.

The Seating model's fields, modes and gestures: DESIGN 12.11-12.17 and Old
